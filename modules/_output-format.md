# 输出格式规范

本 Skill 采用**双输出模式**:先输出审查摘要报告,再以报告为核对清单逐条生成审阅稿/批注稿。

---

## 〇、审查模式(审查前必须确认) ⭐

在开始审查前,**必须先向用户确认审查模式**:

| 模式 | 名称 | 正文处理 | 批注处理 | 适用场景 |
|------|------|---------|---------|---------|
| **模式A** | 修改+批注 | 🔴🟡条款用审阅模式修改(删除原文+插入修改文本),💼条款不修改 | 🔴🟡条款添加修改理由批注,💼条款添加风险提示批注 | 用户确认可以修改合同 |
| **模式B** | 仅批注 | 正文**不做任何修改** | 所有🔴🟡💼条款均添加批注(风险等级+建议) | 用户要求仅做风险提示 |

⚠️ **默认模式**:若用户未明确选择,默认按**模式B**(仅批注)执行。

---

## 一、输出B:审查摘要报告(先输出) ⭐

审查摘要报告必须**先于审阅稿输出**,作为后续生成审阅稿的**核对清单**。

### 一、合同基本信息

```markdown
## 一、合同基本信息

- **合同名称**:______
- **甲方**:______(全称)
- **乙方**:______(全称)
- **签订日期**:______
- **合作主题**:______(一句话概括)
- **审查模式**:模式A(修改+批注) / 模式B(仅批注)
```

### 二、合同类型识别

```markdown
## 二、合同类型识别

✅ **识别类型**:类型[代号]([类型名称])
📋 **识别依据**:[简要说明为何判断为该类型]
👤 **乙方角色**:[在该类型中的角色定位]

⚠️ **立场声明**:本审查从**乙方视角**进行,所有建议倾向于保护乙方利益。
```

### 三、风险概览

```markdown
## 三、风险概览

### 🔴 高风险问题(共 X 项)
1. [问题简述] — 模式A:已在审阅稿中修改 / 模式B:已在批注稿中提示
2. [问题简述] — 同上

### 🟡 中风险问题(共 X 项)
1. [问题简述] — 同上
2. [问题简述] — 同上

### 🟢 低风险问题/建议优化(共 X 项)

### 💼 商务条款风险提示(共 X 项)
1. [条款简述] — 已在审阅稿/批注稿中批注,需当事人确认
```

### 四、审查详情

每个审查项按以下格式:

```markdown
### [条款名称] — 风险等级:🔴/🟡/🟢/💼

**审查状态**:✅ 合规 / ⚠️ 有瑕疵 / ❌ 严重问题 / 🚫 条款缺失 / 💼 商务待确认

**原合同表述**:
> [引用原文]

**问题分析**:
[详细分析]

**法律依据**:
[引用法律条款,格式见 _legal-basis.md 6.1 引用格式]

**修改/批注内容**:
> 🔴🟡(模式A):已在审阅稿中修改为[修改后文本],并添加批注
> 🔴🟡(模式B):已在批注稿中添加批注[批注内容],正文未修改
> 🟢:未修改,建议[优化建议]
> 💼:已在审阅稿/批注稿中批注[批注内容],正文未修改
```

| 序号 | 条款位置 | 风险等级 | 处理方式 | 修改/批注内容 | 法律依据 | 审阅稿已体现✅/❌ |
|------|---------|---------|---------|-------------|---------|----------------|

| 2 | 第X条 | 🟡 | 修改+批注/仅批注 | [修改内容] | [依据] | ❌→✅ |
| 3 | 第X条 | 🟢 | 不修改 | [建议] | - | N/A |
| 4 | 第X条 | 💼 | 仅批注 | [批注内容] | - | ❌→✅ |

⚠️ **核对规则**:生成审阅稿后,必须回查此表,确认所有🔴🟡💼行均为✅。

## 二、输出A:Word 审阅稿/批注稿(后输出)

以审查摘要报告中的"修改建议汇总"为核对清单,**逐条**在原合同上操作。

### 2.1 基本规则

| 项目 | 规范 |
|------|------|
| 修改方式 | **审阅模式(修订模式/Track Changes)** |
| 审阅人名称 | **legal assistant** |
| 输出格式 | **.docx**(Word 格式) |
| 文件命名 | 模式A:`[原合同名]_审查稿_YYYYMMDD.docx` / 模式B:`[原合同名]_批注稿_YYYYMMDD.docx` |

### 2.2 模式A:修改+批注规则

#### 🔴 高风险条款 → 直接修改 + 批注说明

**批注格式**:
```
【🔴高风险】[修改理由]。法律依据:《XXX》第X条。
```

#### 🟡 中风险条款 → 直接修改 + 批注说明

**批注格式**:
```
【🟡中风险】[修改理由]。法律依据:《XXX》第X条。
```

#### 🟢 低风险条款 → 不修改

#### 💼 商务条款 → 只批注不修改

**批注格式**:
```
【💼商务条款】[风险提示]。此条款需合同当事人确认,未做修改。
```

#### 条款缺失时的处理

- 在合同适当位置用审阅模式插入新条款文本
- 批注:【🔴/🟡新增条款】[新增理由]。法律依据:《XXX》第X条。

### 2.3 模式B:仅批注规则

**批注格式**:
```
【🔴/🟡风险提示】[问题分析]。建议修改为:[修改建议]。法律依据:《XXX》第X条。此为风险提示,未修改正文。
```

### 2.4 WPS COM 技术要点 ⭐

#### 关键发现：Find/Replace 不产生 Track Changes

WPS COM 的 `Range.Find.Execute(Replace=2)` 即使在 `TrackRevisions = True` 状态下,**也不会产生修订记录**。必须使用 **Delete + TypeText** 模拟用户输入。

#### 正确的技术流程（模式A）

```
对每条修改:
1. Range.Find.Execute(FindText=原文) → 找到目标范围
2. Selection.SetRange(rng.Start, rng.End) → 选中
3. doc.Comments.Add(Selection.Range, 批注内容) → 添加批注
4. Selection.Delete() → 删除原文（产生修订删除标记）
5. Selection.TypeText(新文) → 键入新文（产生修订插入标记）
   注意：多行文本用 TypeParagraph 处理换行
```

#### 错误做法

| 错误做法 | 后果 |
|---------|------|
| ❌ 使用 Find/Replace 替代 Delete+TypeText | 不产生修订记录,文本被直接替换无痕迹 |
| ❌ 使用 Selection.Find 连续搜索 | 后续搜索从前一次修改位置开始,可能找不到目标 |
| ❌ 先添加所有批注再 Find/Replace | 批注正常但修改不可见 |

#### 搜索技巧

- **使用 Range.Find 而非 Selection.Find**: Range.Find 从文档开头搜索
- **长文本搜索失败时**: 逐步缩短搜索片段重试（30字→20字→15字→10字）
- **换行符处理**: 替换文本中的换行需用 `TypeParagraph()` 替代

#### WPS COM 初始化

```python
wps = win32com.client.Dispatch('Kwps.Application')
wps.UserName = 'legal assistant'
doc = wps.Documents.Open(src)
doc.TrackRevisions = True
```

### 2.5 审阅稿核对机制 ⭐

1. **打开审查摘要报告的"修改建议汇总"表**
2. **逐条核对**:每一条🔴🟡💼的修改/批注是否已在审阅稿中体现
3. **发现遗漏**:立即补充对应修改/批注,不可跳过
4. **全部核对通过后**:在自检声明中确认"审阅稿核对通过"
