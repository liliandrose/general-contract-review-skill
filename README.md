# 通用合同审查助手（乙方视角）

> 从乙方立场审查各类商业合同，基于中国现行法律，采用场景化分流审查模式，自动识别合同类型并加载对应审查要点。

---

## 功能概述

本工具是一个面向律师/法务的合同审查辅助指令集，核心特性：

- **乙方视角锁定**：所有审查建议始终倾向于保护乙方利益，不切换立场
- **9 大合同类型覆盖**：买卖、服务、租赁、承揽、委托、技术、知识产权、广告营销、其他
- **智能类型识别**：根据合同内容自动匹配类型，附带决策树辅助区分易混淆类型
- **双审查模式**：修改+批注（模式A）/ 仅批注（模式B），审查前必须确认
- **风险分级处理**：🔴高风险 / 🟡中风险条款才修改或补充；🟢低风险不改；💼商务条款只批注
- **法律依据可溯源**：所有法律引用来自内置法律依据池，禁止编造
- **六维自检机制**：立场、法律依据、类型一致性、审阅模式、审阅稿核对、质量——审查质量有保障

## 快速开始

### 触发方式

将合同文件或审查需求提供给任意 AI Agent 即可触发，例如：

- "帮我审查这份服务合同"
- "审查一下这个买卖合同的条款"
- "这份承揽合同从乙方角度有什么风险？"

> **适用平台**：本工具以结构化指令（SKILL.md + 模块文件）形式交付，任何能读取 Markdown 指令的 AI Agent 均可加载使用，不限于特定平台。

### 环境要求

生成 Word 审阅稿/批注稿（模式A 或 模式B）时，需要调用 **WPS 的 COM 接口**（`Kwps.Application`）来操作修订模式和批注。因此运行环境需满足：

- **操作系统**：Windows
- **WPS Office**：已安装且已激活（需支持 COM 自动化）
- **Python 依赖**：`pywin32`（用于调用 WPS COM 接口）
- **权限**：Agent 需有本地执行 Python 脚本和启动 WPS 进程的权限

> 若仅输出审查摘要报告（不生成 Word 审阅稿），则无需 WPS 环境。

### 审查流程

```
1. 加载基础模块 → 2. 确认审查模式 → 3. 识别合同类型 → 4. 执行审查 → 5. 自检 → 6. 输出结果
```

#### Step 1：加载基础模块

始终加载以下四个模块：

| 模块 | 文件 | 用途 |
|------|------|------|
| 法律依据池 | `modules/_legal-basis.md` | 所有法律引用的唯一来源 |
| 输出格式规范 | `modules/_output-format.md` | 统一审查报告与审阅稿格式 |
| 通用审查清单 | `modules/_common.md` | 所有合同共通的审查内容 |
| 自检机制 | `modules/_self-check.md` | 六维自检，确保审查质量 |

#### Step 2：审查模式确认（必问）

审查开始前，必须先确认审查模式：

| 模式 | 名称 | 正文处理 | 批注处理 | 输出物 |
|------|------|---------|---------|--------|
| **模式A** | 修改+批注 | 🔴🟡条款用审阅模式修改；💼条款不修改 | 🔴🟡添加修改理由批注；💼添加风险提示批注 | 审查摘要报告 + Word审阅稿 |
| **模式B** | 仅批注 | 正文不做任何修改 | 所有🔴🟡💼条款均添加风险提示批注 | 审查摘要报告 + Word批注稿 |

> 若用户未明确选择，默认按**模式B**（仅批注）执行。

#### Step 3：合同类型识别

根据合同内容匹配类型对照表：

| 代号 | 合同类型 | 乙方角色 | 触发关键词 |
|------|---------|---------|-----------|
| S | 买卖合同 | 卖方/供货方 | 买卖、采购、供货、购销、交付 |
| P | 服务合同 | 服务提供方 | 服务、咨询、代理、外包、委托、顾问、运营 |
| L | 租赁合同 | 出租方 | 租赁、出租、场地、设备、租金 |
| M | 承揽/加工合同 | 承揽方/制作方 | 承揽、加工、定制、制作、委托制作、设计 |
| E | 委托合同 | 受托方 | 委托、代办、代理事务、受托 |
| T | 技术合同 | 技术提供方 | 技术开发、技术转让、技术许可、软件、IT、SaaS |
| I | 知识产权合同 | 权利方/授权方 | 授权、许可、转让、版权、专利、商标、IP |
| A | 广告/营销合同 | 服务提供方 | 广告、营销、推广、策划、品牌、传播、投放 |
| O | 其他合同 | 视具体情况 | 以上均不匹配 |

> **类型识别不明确时**，Skill 会主动追问关键问题，不会强行归类。

#### Step 4：执行审查

1. 合同类型专项审查（根据类型加载对应审查要点）
2. 通用条款审查（`_common.md`）
3. 风险等级标注与建议
4. **先输出审查摘要报告**，确保所有问题全面记录
5. **再根据报告逐项生成审阅稿/批注稿**，以报告中的"修改建议汇总"为清单逐条核对

#### Step 5：自检

按 `_self-check.md` 进行六项自检，未通过则修正后重新自检。

#### Step 6：输出结果

双输出模式，先报告后审阅稿：

- **审查摘要报告**：包含合同基本信息、类型识别、风险概览、审查详情、修改建议汇总、谈判策略提示、自检声明
- **Word 审阅稿/批注稿**：审阅人名称统一为 `legal assistant`，修订模式修改或批注风险提示

## 风险分级规则

| 等级 | 标记 | 正文处理 | 批注处理 |
|------|------|---------|---------|
| 高风险 | 🔴 | 模式A修改 / 模式B仅批注 | 修改理由 + 法律依据 |
| 中风险 | 🟡 | 模式A修改 / 模式B仅批注 | 修改理由 + 法律依据 |
| 低风险 | 🟢 | **不修改** | 仅在报告中列出建议 |
| 商务条款 | 💼 | **不修改** | 仅批注风险提示，需当事人确认 |

**核心原则**：仅对🔴🟡中高风险条款修改；商务条款（合同金额、服务内容等）只批注不修改。

## 乙方通用防守原则

### 🔴 必争底线

1. **赔偿上限**：乙方总赔偿责任不超过已收取费用/合同金额的X%
2. **间接损失排除**：不承担利润损失、商誉损失、惩罚性赔偿等间接损失
3. **违约责任对称**：甲方违约金与乙方违约金应对等
4. **付款保障**：分期付款、迟延付款违约金、付款前提条件

### 🟡 建议争取

5. 解除权对等
6. 通知条款明确
7. 不可抗力包含政府行为、政策变化
8. 管辖选择乙方所在地法院/仲裁机构

### 🟢 可适当让步

9. 保密期限 2-3 年合理
10. 争议解决方式可协商

## 各类型核心审查要点一览

### S类 买卖合同（卖方视角）

付款条款 🔴 → 交付与验收 🔴 → 质保责任 🔴 → 所有权转移 🟡 → 违约对称性 🔴 → 退换货 🟡 → IP归属 🟡

### P类 服务合同（服务方视角）

服务范围边界 🔴 → 付款条款 🔴 → 修改/调整限制 🔴 → 验收标准 🔴 → 乙方责任限定 🔴 → 甲方配合义务 🟡 → IP 🟡

### L类 租赁合同（出租方视角）

租金与支付 🔴 → 使用限制 🔴 → 损坏与修缮 🟡 → 提前退租 🔴 → 保险 🟡 → 期满处理 🟡

### M类 承揽合同（承揽方视角）

工作成果要求 🔴 → 修改次数限制 🔴 → 付款 🔴 → 验收标准 🔴 → 材料设备 🟡 → IP归属 🔴 → 甲方解除权限制 🔴

### E类 委托合同（受托方视角）

委托范围 🔴 → 授权范围 🔴 → 报酬 🔴 → 费用报销 🟡 → 越权责任 🔴 → 解除权限制 🔴

### T类 技术合同（技术提供方视角）

技术范围与使用限制 🔴 → IP保护 🔴 → 技术秘密保密 🔴 → 技术支持 🟡 → 侵权担保 🔴 → 技术改进归属 🟡

### I类 知识产权合同（权利方视角）

授权范围精准化 🔴 → "未明示即未授权"兜底 🔴 → 转授权限制 🔴 → 署名权 🟡 → 使用情况报告 🟡 → 超范围使用违约 🔴

### A类 广告/营销合同（服务方视角）

交付物标准 🔴 → 修改次数限制 🔴 → 付款 🔴 → 甲方审批时限 🔴 → 第三方权利 🟡 → 广告合规 🟡

## 六维自检机制

每次审查输出前必须通过以下六项自检：

| 序号 | 自检项 | 核心问题 |
|------|--------|---------|
| 1 | 立场自检 | 是否始终保持乙方视角？ |
| 2 | 法律依据自检 | 所有引用是否来自法律依据池？ |
| 3 | 合同类型一致性自检 | 是否使用了正确的类型审查思路？ |
| 4 | 质量自检 | 必查条款是否全覆盖？建议是否可操作？ |
| 5 | 审阅模式自检 | 审阅稿是否符合审查模式规范？ |
| 6 | 审阅稿核对自检 | 报告中每一条修改建议是否都在审阅稿中体现？ |

> 任何一项未通过，必须修正后重新自检，全部通过才可输出。

## 输出格式

### 审查摘要报告

```
一、合同基本信息
二、合同类型识别
三、风险概览（🔴🟡🟢💼分级）
四、审查详情（逐条：原合同表述 → 问题分析 → 法律依据 → 修改/批注内容）
五、修改建议汇总（核对清单，审阅稿逐条核对）
六、谈判策略提示（必争/可让步/实务建议）
七、审查自检声明
```

### Word 审阅稿/批注稿

| 项目 | 规范 |
|------|------|
| 修改方式 | 审阅模式（修订模式 / Track Changes） |
| 审阅人名称 | `legal assistant` |
| 输出格式 | `.docx`（Word 格式） |
| 文件命名 | 模式A：`[原合同名]_审查稿_YYYYMMDD.docx`；模式B：`[原合同名]_批注稿_YYYYMMDD.docx` |

批注格式示例：

- 模式A 高风险：`【🔴高风险】[修改理由]。法律依据：《XXX》第X条。`
- 模式A 中风险：`【🟡中风险】[修改理由]。法律依据：《XXX》第X条。`
- 商务条款：`【💼商务条款】[风险提示]。此条款需合同当事人确认，未做修改。`

## 注意事项

1. **角色锁定**：本工具永远从乙方视角审查，不切换立场
2. **审查前必问**：每次审查开始前必须确认审查模式，未确认前不得修改合同正文
3. **先报告后审阅稿**：必须先输出审查摘要报告，再以报告为清单逐条生成审阅稿
4. **法律依据不编造**：所有法律引用必须来自 `modules/_legal-basis.md`，池外引用标注"待核实"
5. **类型识别不明确时追问**：不强行归类，主动向用户追问关键问题
6. **WPS COM 依赖**：生成 Word 审阅稿/批注稿需调用 WPS COM 接口，要求 Windows 环境 + 已安装 WPS + pywin32；仅输出审查摘要报告则无此依赖
6. **平台无关**：指令集以 Markdown 文件交付，任何支持读取结构化指令的 AI Agent 均可使用
